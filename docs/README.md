# 專案文件

本目錄保存 Android 長截圖 App 的產品、設計與驗收文件。每份文件只處理一個主題，避免主規格隨專案成長而失控。

## 文件地圖

檔名編號代表規格層次，由「做什麼」到「怎麼驗證」：

| 文件 | 主題 | 回答的問題 |
| --- | --- | --- |
| [01 產品規劃](01-product-plan.md) | 產品目標、第一版範圍、需求、驗收標準與風險 | 要做什麼、不做什麼 |
| [02 互動規格](02-interaction-design.md) | 畫面流程、懸浮控制、手動修正、輸出與錯誤回饋 | 使用者看到什麼 |
| [03 實作計畫](03-implementation-plan.md) | 已固定的技術決策、責任邊界、資料生命週期與交付順序 | 怎麼蓋出來 |
| [04 拼接規格](04-stitching-spec.md) | 重疊搜尋、可信度、系統列處理、合成與降級規則 | 核心演算法怎麼判斷 |
| [05 測試計畫](05-test-plan.md) | 測試資料、量化指標、實機案例、資源與隱私驗收 | 怎麼判定完成 |

## 建議工作順序

1. 先讀[產品規劃](01-product-plan.md)，確認要做與不做的範圍。
2. 依[實作計畫](03-implementation-plan.md)建立最小可執行 App 與擷取工作階段。
3. 實作個別功能時查閱[互動規格](02-interaction-design.md)與[拼接規格](04-stitching-spec.md)。
4. 每個階段以[測試計畫](05-test-plan.md)的門檻決定是否完成。

## 後續擴充

只有重要決策需要改變且理由必須長期保留時，才新增 `decisions/` 文件；一般實作細節留在程式碼與測試中。
