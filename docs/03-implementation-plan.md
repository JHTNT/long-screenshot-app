# Android 長截圖 App 實作計畫

## 1. 文件目的

本文件把[產品規劃](01-product-plan.md)轉換成可交給 AI 執行的技術邊界、資料流程與交付順序。實作時可自行決定函式與類別名稱，但不得擴張產品範圍或降低驗收條件。

互動行為、拼接規則與測試方法分別定義於：

- [互動規格](02-interaction-design.md)
- [拼接規格](04-stitching-spec.md)
- [測試計畫](05-test-plan.md)

## 2. 已固定的實作決策

| 項目 | 決策 |
| --- | --- |
| 平台 | Android 10（API 29）以上 |
| UI | Kotlin、Jetpack Compose、單一 App module |
| 畫面擷取 | Android MediaProjection；每個工作階段重新取得系統同意；Android 14 起使用者可選整個螢幕或單一應用程式，兩種模式都支援並記錄於工作階段 |
| 執行方式 | 擷取期間使用符合目前目標 Android 版本要求的前景服務；Android 14 起宣告 mediaProjection 前景服務型別與對應權限 |
| 控制方式 | 可拖曳的懸浮按鈕；完成與取消重用前景服務通知動作 |
| 方向 | 僅直向；工作階段中方向或畫面尺寸改變即停止自動處理 |
| 原始圖片 | 以 PNG 保存於 App 私有暫存目錄，不先做有損壓縮 |
| 拼接 | 先用 Android／Kotlin 可直接完成的像素與梯度比對，不引入 OpenCV |
| 成品 | JPG 品質 95 為預設，可選 PNG；不縮放像素寬度 |
| 永久保存 | 使用 MediaStore 寫入相簿 |
| 剪貼簿 | 使用 App 可控的內容 URI；暫存有效期 24 小時 |
| 工作階段 | 同一時間只允許一個；第一版不跨程序死亡恢復 |
| 持久化 | 不使用資料庫；檔案名稱與記憶體狀態已足夠 |
| 網路 | 不宣告網路權限，不加入分析、遙測或雲端功能 |

目標 SDK 與編譯 SDK 使用開發環境中最新的穩定版本，並在 Gradle 設定中固定，不以 Google Play 上架要求決定產品功能。

## 3. 明確不加入的基礎設施

第一版不加入以下項目：

- 依賴注入框架。
- Room 或其他資料庫。
- WorkManager；暫存清理由 App 啟動與工作階段結束處理。
- OpenCV、圖片載入框架或自製外掛架構。
- 多 module、repository pattern 或只有一個實作的介面。
- 背景自動捲動與 AccessibilityService。
- 網路客戶端、帳號、分析或當機回報服務。

只有當測試資料證明現有方案無法達成驗收標準時，才新增對應能力。

## 4. 執行單元

實作只需要下列責任邊界，名稱可依專案慣例調整：

### 4.1 Compose Activity

- 顯示首頁、權限說明、擷取中狀態（含完成與取消）、處理進度、預覽、手動修正及輸出選項。
- 觀察目前工作階段狀態。
- 不直接持有或操作 MediaProjection。
- 不在主執行緒解碼、比對或合成完整圖片。

### 4.2 擷取前景服務

- 持有單次工作階段的 MediaProjection、VirtualDisplay 與 ImageReader。
- 建立、移動、隱藏及恢復懸浮按鈕。
- 接受擷取、完成與取消動作。
- 保證同一時間最多處理一次擷取。
- 服務終止時釋放投影、顯示器、ImageReader 與懸浮視窗。

### 4.3 工作階段協調

- 建立工作階段識別碼及暫存目錄。
- 依序記錄有效圖片、寬高、擷取時間與系統區域提示。
- 管理狀態轉換及錯誤。
- 工作階段完成或銷毀時清理來源與中間檔。

第一版可使用單一程序內狀態持有者，不建立通用狀態機框架。

### 4.4 拼接器

- 接受有順序的圖片清單。
- 逐對產生重疊位置、可信度及失敗原因。
- 產生自動接縫提案，但不修改來源圖片。
- 根據已確認接縫與裁切值產生成品。

拼接器不依賴 Android UI，讓核心幾何與比對可用本機測試直接驗證。

### 4.5 輸出與清理

- 將成品寫入相簿、剪貼簿暫存或直接刪除。
- 確認寫入成功後才刪除工作階段來源。
- App 啟動時刪除未完成的孤兒工作階段，以及超過 24 小時的剪貼簿檔案。
- 清理失敗只記錄必要的本機診斷資訊，不包含圖片內容。

## 5. 工作階段狀態

只允許以下主要狀態：

```text
閒置
  → 取得權限
  → 擷取中
  → 拼接處理中
  → 預覽／手動修正
  → 已保存、已複製或已銷毀
  → 閒置
```

共同規則：

- 取消可從「取得權限」、「擷取中」、「拼接處理中」及「預覽／手動修正」觸發。
- 擷取失敗不必終止整個工作階段；無效圖片不加入序列。
- 投影權限失效、服務被終止、方向改變或畫面尺寸改變時，停止接受新截圖並保留已完成來源。
- 單一應用程式模式下被分享 App 不可見只使單次擷取失敗，不終止工作階段。
- 程序死亡後不恢復編輯；下次啟動清理未完成工作階段。
- 已進入相簿的成品不受工作階段清理影響。

## 6. 暫存資料

每個工作階段使用一個 App 私有目錄：

```text
capture-sessions/<session-id>/
  source-0001.png
  source-0002.png
  ...
  preview.jpg
  result.jpg 或 result.png
```

規則：

- 檔名序號就是擷取順序，不另建資料庫。
- `preview.jpg` 可縮小且可重建，不可作為最終輸出來源。
- 手動裁切、位移與自動配對結果先保存在記憶體；確認輸出時才套用到來源。
- 若後續需要跨程序恢復，再新增單一工作階段描述檔，不預先建立資料層。
- 剪貼簿檔案移到獨立的私有分享目錄，避免工作階段清理使剪貼簿立即失效。

## 7. 擷取流程

### 7.1 開始

1. 檢查是否能顯示懸浮視窗；缺少權限時引導使用者前往系統設定。
2. 取得當次 MediaProjection 同意。
3. 判定使用者選擇的擷取模式（整螢幕或單一應用程式）並記錄於工作階段；單一應用程式模式需監聽內容尺寸與可見性回呼。
4. 啟動前景服務及持續通知。
5. 建立符合目前螢幕尺寸與密度的擷取輸出。
6. 建立工作階段目錄並顯示懸浮按鈕。

任一步驟失敗都要釋放已取得資源，不留下半啟動服務。

### 7.2 單次截圖

1. 拒絕重複點擊；擷取完成前按鈕維持停用。
2. 整螢幕模式：暫時隱藏懸浮按鈕及 App 自己的擷取回饋，等待至少一張不含懸浮按鈕的新畫面，不可重用隱藏前的 ImageReader 緩衝影像。隱藏期間可保留完全透明的觸控攔截層，避免使用者連點誤觸底層 App。
3. 單一應用程式模式：懸浮按鈕不在擷取內容中，不需隱藏；被分享 App 不可見時直接回報失敗，不取用凍結或過時影像。
4. 取得最新有效影像，裁掉 ImageReader 因 row padding 產生的無效右側區域。
5. 以原始寬高寫入下一個 PNG 檔。
6. 關閉本次 Image，恢復懸浮按鈕並更新成功張數。

逾時、空白畫面或檔案寫入失敗時不增加張數，並允許再次擷取。受保護畫面的判定需保守：只有整張近乎純黑（系統以黑畫面取代受保護內容）才自動視為失敗；接近全白的真實內容頁不可誤判為空白。

### 7.3 完成與取消

- 「完成」停止新擷取，釋放投影資源，再開始拼接。
- 沒有有效圖片時直接回首頁並清理。
- 只有一張有效圖片時跳過拼接，直接進入預覽。
- 「取消」先讓使用者確認銷毀；確認後停止服務並清理。

## 8. 拼接與成品

拼接行為以[拼接規格](04-stitching-spec.md)為準。

資源原則：

- 比對時只解碼目前相鄰的兩張圖片；處理完成即釋放。
- 搜尋用縮圖與灰階資料不得取代原始來源。
- 預覽使用縮圖或分段顯示，避免先建立完整成品。
- 產生成品前先估算 `寬 × 高 × 4` 所需記憶體，並與執行時可用記憶體比較。
- 估算顯示無法安全配置時，保留來源並拒絕輸出，不嘗試碰運氣配置。
- JPG 格式高度上限為 65,535 px；估算超過時要求改用 PNG 或減少張數，PNG 的實際上限由記憶體估算把關。
- 第一版不做自製串流 JPG／PNG 編碼器；若實機可接受高度不足，再以測試結果決定是否升級。

## 9. 輸出流程

### 9.1 保存到相簿

1. 依使用者選擇產生 JPG 或 PNG。
2. 透過 MediaStore 建立尚未完成的相簿項目。
3. 寫入並關閉成功後，才標示為可見成品。
4. 確認相簿項目可讀後，清除工作階段。
5. 寫入失敗時移除不完整項目並保留工作階段供重試。

### 9.2 複製到剪貼簿

1. 將成品移至 FileProvider 可提供的私有分享目錄。
2. 放入包含 MIME type 的內容 URI，不使用裸檔案路徑。
3. 顯示「剪貼簿圖片最多保留 24 小時」。
4. 清除其他工作階段來源。
5. 下次 App 啟動時刪除已超過 24 小時的剪貼簿檔案。

### 9.3 銷毀

- 不建立相簿項目或剪貼簿內容。
- 刪除來源、預覽、成品與工作階段目錄。
- 刪除失敗時顯示失敗，不宣稱已完全銷毀。

## 10. 執行緒與取消

- UI 與懸浮視窗操作在主執行緒。
- 圖片讀寫、比對及合成在背景執行緒。
- 同一工作階段只允許一個擷取工作與一個拼接工作。
- 新的「完成」或「取消」動作不得啟動重複工作。
- 取消長時間處理時，完成目前不可中斷的檔案操作後立即停止，並刪除未完成成品。
- 所有 Bitmap、Image、檔案串流、VirtualDisplay 及 MediaProjection 都必須在最接近持有者的位置釋放。

## 11. 診斷資訊

只記錄下列非敏感資訊：

- 工作階段內圖片張數與尺寸。
- 每個接縫的候選位移、分數、可信度與拒絕原因。
- 處理時間、記憶體估算與例外類型。
- 權限或服務狀態。

不得記錄圖片像素、OCR 文字、檔名以外的來源 App 內容或可識別私人資訊。正式成品不包含浮水印或除錯標記。

## 12. 實作順序

1. 建立最小 Compose App、首頁與狀態顯示。
2. 完成權限、前景服務、MediaProjection 與懸浮按鈕。
3. 在實機證明懸浮按鈕不會出現在來源 PNG。
4. 完成工作階段目錄、逐張擷取、取消與啟動清理。
5. 完成單張預覽、相簿、剪貼簿與銷毀。
6. 依[拼接規格](04-stitching-spec.md)實作純邏輯拼接器及自動預覽。
7. 依[互動規格](02-interaction-design.md)完成手動修正。
8. 通過[測試計畫](05-test-plan.md)中的階段門檻。

每一步都保持可執行；未通過前一步的實機驗證，不提前增加後續抽象。
